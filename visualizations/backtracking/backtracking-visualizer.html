Read me first — the one mental model + where to learn it

Backtracking is ONE algorithm. It's a depth-first walk of a decision tree: try a choice, recurse, then undo it — exploring every path but abandoning ("pruning") the ones that can't lead to a valid solution. Learn one template and every tab below is just that template with three blanks filled in.

The universal template

def backtrack(state, choices, results):
    if is_complete(state):            # ← BASE CASE
        results.append(copy(state))
        return
    for choice in available(state):   # ← CHOICES (+ pruning)
        make_choice(state, choice)    # 1. CHOOSE
        backtrack(state, choices, results)  # 2. EXPLORE
        undo_choice(state, choice)    # 3. UNCHOOSE

This is the template from AlgoMaster's backtracking guide — the primary source this tool is built around.

The three steps (the heartbeat)

state.append(x)  → 1. CHOOSE
backtrack(...)  → 2. EXPLORE
state.pop()  → 3. UNCHOOSE

Analogy: you're walking a maze dropping a breadcrumb at each step (append). When a path dead-ends or succeeds, you walk back picking the breadcrumb up (pop) to try the next turn. The UNCHOOSE (pop) is the step everyone forgets — this tool makes it loud.

Every problem = the template + 3 knobs

Open any tab and read the strip under the controls. It shows the only things that change between problems:

  • ① is_complete? — when do we record? (subsets: always · combinations: len==k · combo-sum: total==target · palindrome: start==len(s))
  • ② available choices — what does the for loop iterate, and what gets pruned?
  • ③ reuse an element? — the next call's start is i (reuse, Combination Sum) vs i+1 (no reuse, everything else).

Handling duplicates (Combination Sum II)

Sort first, then skip a choice when i > start and nums[i] == nums[i-1]. That skips repeats at the same tree depth (which is what creates duplicate combos) while still allowing that value deeper down. It's i > start, not i > 0, for exactly that reason.

Cutting a string instead of picking numbers (Palindrome Partitioning, LC 131)

What the problem asks. Given s = "aab", chop it into consecutive pieces so that every single piece reads the same forwards and backwards. Return every possible way. For "aab" there are exactly two: ["a","a","b"] and ["aa","b"]. The one-piece answer ["aab"] fails, because "aab" reversed is "baa". Note the pieces are always in order and touching — you never rearrange or drop characters, you only decide where the scissors go.

The one reframe that makes it click. You are not choosing which characters to take — the characters are fixed. You are choosing where to put the cuts. A string of length n has n−1 gaps between characters, and each gap is either cut or not cut:

   a   a   b          # the string
     ↑   ↑            # 2 gaps → 2² = 4 ways to cut

  a | a | b    ✓ every piece is a palindrome  → keep
  aa  | b      ✓ "aa" is a palindrome         → keep
  a | ab       ✗ "ab" reversed is "ba"        → reject
  aab          ✗ "aab" reversed is "baa"      → reject

So it's the same yes/no decision tree as Subsets, wearing a costume. Backtracking's whole job is to walk those 4 candidates without building them all first — and to abandon a branch the instant a piece fails the palindrome test.

Why one number, start, is the entire state. The moment you cut "a" off the front of "aab", what's left is "partition ab" — the exact same problem, just smaller. So start means: "every character before index start is already safely cut into palindromes; your job is the rest." That's also why the base case is start == len(s): you've run out of string, which means every character got used and every piece already passed the palindrome check on its way in — so whatever is in state is a valid answer, no final verification needed.

The three blanks, filled in.

  • ① is_complete? start == len(s) — the string is used up.
  • ② available choices — the for end loop slides the cut one character further each time. From start=0 in "aab" the candidate pieces are "a", then "aa", then "aab". That loop is the only place choices come from.
  • ③ pruning if not is_pal(piece): continue — a piece that isn't a palindrome can't appear in any answer, so don't recurse into it; just try a longer piece instead. continue (skip this one choice), not break — a longer piece can still be a palindrome even when a shorter one wasn't ("ab" ✗ but "aba" ✓).
  • ④ reuse? No. The next call starts at end + 1 — right after the piece you just committed — so no character is ever used twice.

The one line that confuses everyone: piece = s[start:end + 1]. Python slices are end-exclusive, so to include the character sitting at index end you have to slice up to end + 1. The +1 is Python bookkeeping, not algorithm. Same for t[::-1] — that's just "t reversed".

When you step the tab: the string panel shows green characters = pieces already committed (with a ✂ at each committed cut), gold = the piece being tested right now, dim = the part you haven't reached. Watch what happens after ["a","a","b"] is recorded: the pops walk you all the way back to start=0, and the loop tries the longer piece "aa". That un-choosing is the entire point of backtracking.

Same template on a grid (Word Search, LC 79)

Nothing new — only the three blanks change. The choices are the 4 neighbours instead of a for i in range(...); the state is the path of cells you've stepped on; and CHOOSE / UNCHOOSE is board[r][c] = '#' … board[r][c] = word[i]. That mark-and-restore is the visited set — no separate seen structure needed, and restoring it on the way out is what lets a different path reuse the cell.

Two details worth noticing while you step it: (1) the bounds test comes first in the or chain, so board[r][c] is never indexed out of range; (2) since word[i] is a letter, word[i] != board[r][c] already rejects a '#' cell — the explicit board[r][c] == '#' check is belt-and-braces, and the visualizer labels that case separately so you can see which rule did the pruning.
